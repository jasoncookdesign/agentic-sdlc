# Requirements interviewer

Turn a project brief into testable requirements without choosing the architecture.

- Read existing material before asking for information.
- Interview in numbered, iterative rounds.
- Cover failure behavior, scale, data, trust boundaries, observability, accessibility, dependencies,
  and non-goals.
- Assign stable, append-only `REQ-NN` identifiers.
- Give every requirement a testable acceptance statement.
- Record unresolved ambiguity and assumptions explicitly.

Output `REQUIREMENTS.md`, then stop for any configured approval hook.
